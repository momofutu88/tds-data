## 一、核心原则（本方案的地基）

1. **执行权归平台**：所有纪律（止损、止盈）由币安跟单系统服务器端执行，零延迟、不依赖人醒着。
2. **推送只做记账**：任何邮件/ntfy 推送降级为流水账和复盘依据，**不作为任何操作的触发依据**。
3. **唯一有效警报**：币安 App 的止盈/止损触发推送（用户已开启通知权限）。
4. **提现是锁利之后的事**：止盈触发后利润已变现金，回吐风险归零，提现不再有时效。

## 三、触发后的「重跟三步」（唯一的人工动作）

平台止盈触发 = 自动停止跟单。收到币安推送后执行：

1. **重跟**：暴力组按原保证金重跟（爽翻天 500U）；复利组以「本金+利润」重跟。
2. **设止盈**：爽翻天每次重跟设 **20%**；复利组每次重跟设 **200%**。
3. **设止损**：新止损 = max(原止损, 新保证金 × 0.6)。

## 四、各组的完整纪律栈

**暴力组（爽翻天）**：
- 平台止盈 +20% 是第一执行线（法兰西验证过此类号回吐以分钟计）。
- 原提现阶梯（25%→提20%M、50%→50%M、100%→本金全回）自止盈上线起**降级为参考**：+20% 平台先锁，人工提现不再抢时间。

**复利组（TDS / 1000万u / Sky）**：
- 平台止盈 +200% = 提现纪律「账户封顶 2M」的自动执行器：触发即平仓，账户变回本金+一倍利润，重跟继续复利。
- +200% 之前不锁利、不打断复利。

## 五、适用边界（已确认的残余风险，不隐瞒）

**+30%~+100% 区间的浮盈回吐，目前没有自动保护。**

- 平台止盈只有固定线，币安没有回撤型（trailing）止盈。
- 被停用的 4 小时扫描也从未覆盖该区间——它只统计已平仓，浮盈不可见。
- 当前缓解：复利组为 3x×16 仓分散结构，实证回吐以天计；暴力组已被 +20% 固定线封死大回吐空间。
- **终局方案（12 月）**：VPS 上线后用**只读 API Key** 直读 4 个账户实时权益，引擎内置「利润从峰值回吐 50% → 推送+标记」熔断。只读 Key 无交易权限，风险为零。在此之前该区间为「已接受的暴露」。

## 八、已知限制

- 止盈触发后自动停止跟单，需手动重跟（无 API 可代劳，见第三节三步）。
- 止盈线为固定比例，不随峰值回撤（见第五节）。
- 项目止损（USDT 金额）在锁定期内不可修改。
- 接口推算与 App「净盈亏」存在偏差（已平仓口径偏低 20~25%，浮盈不可见），一切以 App 为准。
